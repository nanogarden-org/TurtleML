# TurtleML Related Work and Adjacent Prior Art

TurtleML is intentionally documented alongside neighboring ideas rather than presented as though recursion, composition, graph structure, modularity, or hierarchical systems began with this project.

This document records adjacent work that helps clarify TurtleML's scope and intellectual neighborhood.

## MorphoHDL

**MorphoHDL** is an experimental hardware description language and graph-rewrite system from the `paradigms-of-intelligence/morpho` repository. Its README describes it as:

> A minimalistic language for growing circuits through structural recursion.

MorphoHDL recursively replaces or divides cells into subcells while growing logical connectivity and physical structure. Its published documentation identifies Parametric L-Systems and functional hardware-description languages as inspirations.

Canonical repository:

`https://github.com/paradigms-of-intelligence/morpho`

### Shared territory

MorphoHDL and TurtleML both occupy a broader design territory involving:

- recursion;
- composition;
- locally specified structure;
- graph-like connectivity;
- repeated rules across scales; and
- systems whose large form emerges from smaller interacting units.

That overlap is valuable. It demonstrates that recursive structural ideas can produce useful computational artifacts rather than existing only as metaphor.

### Important distinction

MorphoHDL's central operation is **recursive structural rewriting**: rules transform cells into smaller cells and thereby generate circuit or graph structure.

TurtleML's central concern is **recursive operational composition**: bounded systems interact through explicit exchange contracts while retaining meaningful internal state, behavior, control, policy, or identity at their own scale.

A concise comparison is:

| Dimension | MorphoHDL | TurtleML |
| --- | --- | --- |
| Primary unit | cell | turtle / bounded operational system |
| Primary operation | divide / replace / rewrite | compose / contain / connect |
| Recursive focus | structural generation | operational composition |
| Boundary concern | connectivity produced by rewrite | explicit exchange contract |
| Typical internal concern | generated topology / circuit structure | local behavior, state, control, policy, capabilities |
| Heterogeneous internals | not the primary abstraction | explicitly expected |
| Primary domain | circuits and graphs | heterogeneous systems and systems-of-systems |

This is a conceptual distinction, not a claim that the two projects are disjoint in every implementation.

### Potential composition

The projects can be complementary.

For example, a TurtleML turtle could internally contain a circuit generated by MorphoHDL while exposing a TurtleML exchange contract to the surrounding system:

```text
TurtleML parent
┌─────────────────────────────────┐
│                                 │
│   Turtle A                      │
│   ┌─────────────────────────┐   │
│   │ MorphoHDL-grown circuit │   │
│   └─────────────────────────┘   │
│          │                      │
│          │ exchange contract    │
│          v                      │
│      Turtle B                   │
│                                 │
└─────────────────────────────────┘
```

In that arrangement, MorphoHDL answers a question like:

> How can this internal computational structure grow recursively?

while TurtleML answers a different question:

> How can this operational unit participate recursively inside larger systems through a legible boundary?

## Provenance policy for related work

When a neighboring project is discovered after TurtleML development has begun, the project should record it rather than erase or minimize it.

The preferred procedure is:

1. record the neighboring work and a stable reference;
2. identify genuine overlap;
3. identify genuine differences without exaggerating them;
4. distinguish known influence from independent convergence;
5. revise TurtleML terminology or claims if prior art makes them too broad; and
6. preserve the comparison in repository history.

The purpose of provenance is not to manufacture isolation. It is to make lineage, convergence, borrowing, and divergence visible.
